# 语言包编写指南

本文档面向语言包维护者，说明如何编写、检查和挂载 Miaoverse 的国际化 TOML 语言包。

## 文件位置

服务默认从 `./locales` 目录加载语言包：

```text
locales/
  zh-CN.toml
  en-US.toml
  ja-JP.toml
```

也可以通过 `config.yaml` 指定外部目录：

```yaml
i18n:
  dir: "/app/locales"
  default_language: "zh-CN"
```

容器部署时，把宿主机语言包目录挂载到 `i18n.dir` 即可。

## 文件命名

推荐使用 BCP 47 语言标签作为文件名：

```text
zh-CN.toml
en-US.toml
pt-BR.toml
```

文件内也应写明语言：

```toml
language = "en-US"
```

如果没有写 `language`，系统会尝试从文件名推断语言。

## 基础结构

语言包由两类内容组成：

- `[messages]`：普通提示文案。
- `[plurals."key"]`：需要单复数变化的文案。

示例：

```toml
language = "en-US"

[messages]
"ok.login" = "Login successful"
"error.bad_request" = "Invalid request. Please check the parameters."

[plurals."mail.unread"]
zero = "No unread messages"
one = "{{count}} unread message"
other = "{{count}} unread messages"
```

## 普通文案

普通文案写在 `[messages]` 下，key 必须与代码中的消息 key 对应：

```toml
[messages]
"ok.sms_sent" = "SMS sent successfully"
"ok.login" = "Login successful"
"error.sms_code_invalid" = "The verification code is incorrect or does not exist. Please try again."
```

建议：

- key 不要翻译，只翻译右侧文本。
- 保留原 key 的层级命名，例如 `error.*`、`ok.*`、`sms.*`。
- 句子尽量完整，不要把一句话拆成多个 key 后在代码里拼接。

## 变量占位符

语言包支持 `{{name}}` 形式的命名变量：

```toml
[messages]
"error.sms_provider" = "SMS provider error: {{error}}. Please contact an administrator."
```

规则：

- 占位符名称只能使用字母、数字、下划线、点和短横线。
- 翻译时必须保留占位符名称，例如 `{{error}}` 不能改成 `{{错误}}`。
- 可以调整占位符在句子中的位置，以符合目标语言语序。

## 单复数

需要根据数量变化的文案写成 `[plurals."key"]`：

```toml
[plurals."example.items"]
zero = "No items"
one = "{{count}} item"
other = "{{count}} items"
```

当前支持的形式：

| 字段 | 用途 |
| --- | --- |
| `zero` | 数量为 `0` 时 |
| `one` | 数量为 `1` 时 |
| `two` | 数量为 `2` 时 |
| `few` | 少量，当前用于 `2-4` |
| `many` | 较多，当前用于 `>=5` |
| `other` | 默认兜底，强烈建议总是填写 |

中文通常不区分单复数，也建议写 `other`：

```toml
[plurals."example.items"]
zero = "没有项目"
one = "{{count}} 个项目"
other = "{{count}} 个项目"
```

英文至少建议写 `one` 和 `other`：

```toml
[plurals."example.items"]
one = "{{count}} item"
other = "{{count}} items"
```

## 当前内置 key

下面是当前接口响应和短信场景使用到的 key：

```toml
[messages]
"error.bad_request" = ""
"error.request_timeout" = ""
"error.server_internal" = ""
"error.server_contact_admin" = ""
"error.sms_provider" = ""
"error.sms_code_invalid" = ""
"error.phone_has_no_account" = ""
"error.no_pending_login_account" = ""
"error.account_not_belong_phone" = ""
"ok.sms_sent" = ""
"ok.login" = ""
"ok.register_and_login" = ""
"ok.new_account_and_login" = ""
"ok.choose_login_account" = ""
"sms.action.login_register" = ""
```

其中 `error.sms_provider` 需要保留 `{{error}}`：

```toml
"error.sms_provider" = "SMS provider error: {{error}}. Please contact an administrator."
```

## 回退规则

请求语言来自 HTTP 请求头 `Accept-Language`。

系统会按以下顺序查找：

1. 请求头指定的语言，例如 `en-US`。
2. 同语种的已加载语言，例如请求 `en-GB`，存在 `en-US` 时可回退到 `en-US`。
3. 配置的 `default_language`。
4. 内置 `zh-CN`。
5. 如果所有语言都没有该 key，直接返回 key 名称，方便发现漏翻。

## 编写检查清单

提交或挂载语言包前，建议检查：

- TOML 语法有效。
- `language` 与文件名一致。
- 所有必须 key 都存在。
- 所有 `{{变量}}` 都被保留，名称未被翻译。
- 单复数文案至少包含 `other`。
- 文案中不包含多余换行、调试文本或 HTML 片段。
- 错误提示语气统一，成功提示语气统一。

## 常见问题

### 新语言包没有生效

检查：

- 文件是否在 `i18n.dir` 指定目录下。
- 文件扩展名是否为 `.toml`。
- `language` 是否写成了正确格式，例如 `en-US`。
- 请求是否带了匹配的 `Accept-Language`。

### 返回了 key 名称

这表示当前语言和兜底语言中都没有找到该 key。把缺失 key 补进对应 TOML 文件即可。

### 变量没有被替换

检查占位符名称是否和代码传入的变量名完全一致。例如语言包写的是 `{{error}}`，代码也必须传入 `error`。
