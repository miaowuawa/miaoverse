# 构建与数据库迁移指南

## 跨平台构建

支持构建 linux 和 windows 两种版本的可执行文件。

### Windows（PowerShell）

```powershell
.\scripts\build.ps1
```

参数：

- `-Platforms linux,windows`：指定要构建的平台（默认同时构建两个）。
- `-Platforms windows`：只构建 windows。

产物输出到 `backend\dist\`：

| 平台 | 产物 |
| ---- | ---- |
| linux amd64 | `dist/miaoverse-linux-amd64` |
| windows amd64 | `dist/miaoverse-windows-amd64.exe` |

### Linux / macOS（Makefile）

```bash
make build-linux    # 构建 linux amd64
make build-windows  # 构建 windows amd64
make build          # 构建当前平台
make run            # 本地运行
make test           # 运行测试
```

构建时关闭 CGO 并使用 `-trimpath`，二进制不依赖系统库，可跨发行版运行。

## Docker 镜像

### 构建

```bash
docker build -t miaoverse-backend .
```

镜像使用多阶段构建（golang:1.25-alpine 编译 + alpine:3.20 运行），包含 `locales/` 语言包和时区数据。

### 运行

```bash
docker run -d --name miaoverse \
  -p 3000:3000 \
  -v /path/to/config.yaml:/app/config.yaml \
  miaoverse-backend
```

注意：

- 配置文件通过挂载注入（默认读取工作目录下 `config.yaml`），不要把含密钥的配置文件打进镜像。
- 容器端口默认 3000，可在配置中修改。
- 首次启动会自动执行数据库迁移（见下）。

## 数据库自动迁移（Automigration）

### 机制

- 服务启动时自动把数据库结构迁移到最新版本，迁移失败会阻止启动。
- 版本记录保存在 `schema_migrations` 表（`version` / `name` / `applied_at`）。
- 迁移文件位于 `service/DBMigration/migrations/`，格式为 `{8位序号}_{名称}.sql`，例如 `0001_baseline.sql`、`0002_add_xxx.sql`。
- 迁移使用独立连接池执行（DSN 额外开启 `multiStatements=true`），主业务连接池不开启该选项，避免扩大注入面。
- 启动时按序号从小到大依次执行未应用的迁移；每个迁移在独立事务中执行，失败回滚该迁移并报错，已成功的迁移不受影响。

### 新增迁移的步骤

1. 修改 `scripts/db.sql`，保持完整建库脚本为最新。
2. 在 `service/DBMigration/migrations/` 下添加新的序号文件，例如：

   ```sql
   -- 0002_add_user_profile_columns.sql
   ALTER TABLE `user` ADD COLUMN `hobby` VARCHAR(255) NOT NULL DEFAULT '' COMMENT 'hobby';
   ```

3. 迁移文件使用纯 SQL，可包含多条语句；**不要**手动操作 `schema_migrations` 表。
4. 不要修改或删除已提交的旧迁移文件。

### 老库兼容

已有库没有 `schema_migrations` 表时，会自动创建并按迁移文件补齐结构；`0001_baseline.sql` 全部使用 `CREATE TABLE IF NOT EXISTS`，对已有表幂等，不会重复建表或丢数据。

## 变更规范

任何数据库变更（新增表、新增字段、改索引等）必须同时满足：

- `scripts/db.sql` 同步更新。
- `service/DBMigration/migrations/` 添加对应迁移文件。

两者缺一即视为数据库变更不完整。
