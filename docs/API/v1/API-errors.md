# 自定义业务错误码文档

## 规则

- 自定义业务错误码用于在 HTTP 状态码之外，向客户端传递更细粒度的业务错误语义。
- 编码规则：`HTTP 状态码 + 两位序号`。例如 `40301` 表示 HTTP `403` 下的第 1 个业务错误。
- 自定义错误码出现在响应 body 的 `code` 字段中，HTTP 状态码保持不变。
- 客户端应优先判断 body 中的 `code`，再判断 HTTP 状态码。

## 错误码列表

| 错误码 | HTTP 状态码 | 含义 | 触发场景 |
| --- | --- | --- | --- |
| `40301` | `403` | 拉黑/被拉黑关系导致无法访问 | 查看者与目标用户之间存在任意一方的拉黑关系（查看者拉黑对方，或对方拉黑查看者），访问对方内容列表、文件等资源时返回 |
| `40302` | `403` | 权限封禁 | 当前用户存在生效中的权限封禁记录（`punishment` 表），且封禁的权限位包含本次操作所需权限（如发布动态、发表评论）时返回 |
| `40303` | `403` | 账号封禁（不允许登录） | 账号状态为封禁（`user.status = 2`），所有登录态接口统一拒绝 |
| `40304` | `403` | 目标用户已被封禁 | 查询其他用户信息时，目标用户的账号状态为封禁（`user.status = 2`）时返回 |
| `45101` | `451` | 内容被屏蔽 | 获取的动态/评论/文章等内容被标记为屏蔽状态（`*StatusBlocked`，如违规内容）时返回 |
| `20001` | `200` | 未登录查看受限内容 | 未登录查看文章，仅返回正文前 60%（小说前 2 章），登录后返回完整内容 |
| `20006` | `200` | 文章过长需分段拉取 | 文章交付正文超过单段上限（100 千字），需使用分段接口 `/articles/:id/segments/:seq` 逐段拉取 |

## 响应示例

拉黑关系拒绝：

```json
{
  "code": 40301,
  "msg": "由于对方权限设置，无法查看此内容"
}
```

权限封禁拒绝：

```json
{
  "code": 40302,
  "msg": "账号封禁期间无法执行此操作"
}
```

账号封禁拒绝：

```json
{
  "code": 40303,
  "msg": "账号被封禁，无法继续操作"
}
```

目标用户被封禁（查询他人信息时）：

```json
{
  "code": 40304,
  "msg": "该用户存在违规记录，部分功能受限"
}
```

内容被屏蔽（获取被屏蔽的动态/评论等）：

```json
{
  "code": 45101,
  "msg": "内容因违规被屏蔽，无法显示"
}
```

未登录查看文章（正文被截断，HTTP 状态码为 `200`）：

```json
{
  "code": 20001,
  "msg": "登录后查看完整内容"
}
```

文章过长需分段拉取（HTTP 状态码为 `200`）：

```json
{
  "code": 20006,
  "msg": "文章过长，请使用分段接口获取正文"
}
```

## 使用约定

- 所有因拉黑关系导致的拒绝，body 中的 `code` 统一为 `40301`，msg 使用 `error.blocked_by_relation`。
- 权限封禁（`punishment` 表对应权限位被禁）统一为 `40302`，msg 使用 `error.punished`。
- 账号封禁（`user.status = 2`，不允许登录）统一为 `40303`，msg 使用 `error.account_banned`。
- 查询其他用户信息时，目标账号被封禁统一为 `40304`，msg 使用 `error.target_punished`。
- 内容被屏蔽（动态/评论/文章等 `*StatusBlocked` 状态）统一为 `45101`，HTTP 状态码为 `451`，msg 使用 `error.content_blocked`。
- 未登录访问受限内容（文章前 60%/小说前 2 章之外的正文）统一为 `20001`，HTTP 状态码为 `200`，msg 使用 `ok.article_fetched_partial`。
- 文章交付正文超长需分段拉取统一为 `20006`，HTTP 状态码为 `200`，msg 使用 `ok.article_need_segments`。
- 新增自定义错误码时，必须同步更新本文档，并在 `consts/errcode.go` 中定义常量。
